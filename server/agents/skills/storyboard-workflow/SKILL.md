# Storyboard 创作流程

## 术语表

视频 > 镜头组 > 结构层级 > 镜头 > 帧。结构层级是逐镜拉片表的一行，镜头是 Storyline 里一个 `**[MM:SS.mmm-MM:SS.mmm]**` 块，镜头组是提交给视频生成的最小单元——连续多个结构层级、总时长 4-30 秒。

- **拆解文件**：`video_parser_md` 解析参考视频的产物，落在 `video/` 下。第 2 节是结构骨架，第 3 节「出场清单」列出场实体，第 4 节是逐镜底稿；第 2 节的「结构节点」与拉片表的「结构层级」一一对应，前者描述叙事功能，后者承载逐镜内容。
- **出场实体**：新片里的人物、产品和场景。每个实体有三样东西——**实体名**是指代键，全流程用它点名（人物名、品类词或 `产品X「品类」`、场景名）；**锚点**是它的文字设定，即角色设定块里该实体冒号后的那段外观描述；**参考图**是它的图像参照，素材里有图的用素材图，没有的在 4a 补拍一张。

## 输入

消息固定带三项信息：目标画幅、目标时长、需求描述。素材以媒体 tag 出现在消息中——图片为 `<image url="..."></image>`，视频为 `<video url="..."></video>`（可带 `name="文件名"`），URL 是媒体的唯一身份。

- 目标画幅与目标时长以最近一条消息给出的值为准。
- 需求描述是创作意图的唯一来源：改编模式倾向、品类、卖点、受众、限制，以及对白原文，都从这里获取。

## 定位

用 `list_files` 看当前文件，按下表从上往下读，第一条命中的就是本次起点：

| 已有文件 | 起点 |
|---|---|
| `video_shot.json` 非空 | 已交付。|
| `storyboard.md` 存在 | 第 4 步，从 4a 开始。|
| 以上都没有 | 第 1 步 |

文件是进度的唯一依据，以 `list_files` 的结果为准。

## 1. 改编模式判定

两种模式：

- **B. 完全复刻参考视频**：结构、动作、运镜、节奏 1:1 复刻，只替换产品、人物、场景中需要替换的维度，对白随新产品改写。
- **C. 完全复刻参考视频动作**：动作设计、镜头结构、剪辑节奏 1:1 复刻，人物、场景、产品、对白和叙事内容按新需求重写。

从需求描述判定：

1. 明确指定 C，或明确表达"只要它的动作 / 镜头节奏，内容换掉"→ C。
2. 其余一律 B。

## 2. 素材与基础信息

**2a 素材事实清单**：用户输入的图片可直接观察；不在上下文中的图片（历史图片、工具产出图片 URL）用 `ReadMediaFile(url)` 读取。把看到的图片内容按下面的要求汇总成一张表：

| 类型 | 名称 | 辨识特征 | 来源图 |
| :--- | :--- | :--- | :--- |
| 人物 | 辨识性短名 | 性别年龄、服装、发型、标志性特征 | 该图媒体 tag 的 url |
| 场景 | 辨识性短名 | 空间类型、核心陈设、材质 | 该图媒体 tag 的 url |
| 产品 | 品类词；多产品时 `产品X「品类」` | 颜色、材质、关键设计细节 | 该图媒体 tag 的 url |

类型只取人物、场景、产品三种，按此顺序分组；名称列就是各实体的实体名。产品一张图一行，同一产品的多个视角写相同名称；人物和场景如果是同一实体只占一行。辨识特征只写图上直接看得到的。

- 产品行合称**产品事实清单**，是后续所有产品外观描述的唯一来源；人物图、场景图里的服装道具不算。
- 有两个及以上不同产品时，名称用 `产品X「品类」`（如 `产品A「儿童凉鞋」`），后续都用这个名称指代该产品；单产品直接用品类词。

**【示例】**
*(只示意表格结构与辨识特征的描述方式，不代表正式请求中素材；条目数量以实际图片为准。示例里三张产品图是同一双鞋的不同视角，各占一行、名称相同。)*

| 类型 | 名称 | 辨识特征 | 来源图 |
| :--- | :--- | :--- | :--- |
| 人物 | 金发女性 | 一位 25 岁上下的白人女性，中等身高，身形偏瘦，皮肤白皙，脸型清瘦，鼻梁挺直。她留着一头浅金色的直发，长度到肩膀，发尾微微向内扣。她穿着宽松的米色粗针织开衫和黑色直筒裤。 | `https://…/p1.jpg` |
| 场景 | 入户门厅 | 地面铺着浅色的橡木地板，墙面下半截是白色的护墙板，上半截刷成米白色。门边装着一排挂衣钩，下面放着一张矮凳。 | `https://…/s1.jpg` |
| 产品 | 儿童凉鞋 | 正面：藕粉色软质 EVA 鞋身，双排魔术贴，鞋头包覆 | `https://…/prod-1.jpg` |
| 产品 | 儿童凉鞋 | 侧面：鞋侧镂空透气孔，后跟提手带 | `https://…/prod-2.jpg` |
| 产品 | 儿童凉鞋 | 鞋底：浅灰橡胶大底，波浪防滑纹 | `https://…/prod-3.jpg` |

**2b 解析参考视频**：对每个视频 tag 调用 `video_parser_md(video_url="...")`，产出 `video/` 下的视频拆解文件；`video/` 下已有拆解文件时直接复用，不重复解析。


**2c 基础信息**：逐字段确定并标注来源。

| 字段 | 来源 |
|---|---|
| 品类 | 需求描述中给出时以其为准；否则取产品事实清单中的名称 |
| 核心商业卖点 / 核心策略 / 目标受众 | 需求描述优先；未给出时从素材信息中推断，标注「素材推断」 |
| 视频尺寸 | 需求描述中的目标画幅 |
| 视频时长 | 需求描述中的目标时长 |
| 使用场景 | 需求描述或素材推断 |
| 已知限制 | 需求描述中有就填 |


## 3. 逐镜拉片表

**3a 读 reference**：用 `get_skill_reference("storyboard-workflow", "<文件名>")` 读取 storyboard-spec.md 和对应模式的 reference。

1. `storyboard-spec.md`：两种模式共用的规则——镜头继承规则、硬约束、粒度标尺和 `storyboard.md` 文件格式。
2. 第 1 步判定模式对应的模式 reference：该模式专有的替换范围、改写边界与展开路径。B → `exact-replica.md`，C → `action-reference.md`，只读命中的那一份。

**3b 读拆解文件**：用 `list_files` 找到 `video/` 下的视频拆解文件，`read_file` 读全文。第 2 节的结构节点是骨架，第 3 节「出场清单」是锚点的数据来源，第 4 节的镜头划分、画面事实与 `{ }` 里的台词是改写底稿。

拆解文件异常（第 2 节结构节点与第 4 节的结构层级数或名称对不上、结构层级重复出现）时，对该视频重新调用一次 `video_parser_md` 再继续，不自行改写拆解文件正文。

**3c 锚点**：拆解文件第 3 节「出场清单」列出了参考视频里出现的人物、产品和场景，逐个把它们锚定到新片的实体上。取值按先后顺序走：素材事实清单里有对应图的，按图写；没有图的，先按 3a 模式 reference 的替换规则定归属；模式规则没定死的，再从需求描述与第 2 步基础信息推断；什么都推不出的才沿用「出场清单」的实体。

推断人物时，先看他在片中怎么和产品打交道（拆解文件第 4 节有记录）：穿戴、实穿试用产品的人必须是产品的可信使用者，儿童产品的穿着者就是儿童；只手持讲解、带货展示的人不必是使用者，按需求描述和受众定人设。推断场景时看使用场景。

一个实体一行，实体名加锚点，写进 `storyboard.md` 开头的角色设定块，条目格式见 `storyboard-spec.md`。

**3d 改写 Storyline**：逐个结构层级往下写，人物、产品和场景一律按 3c 锚点替换，不回头抄参考视频；结构层级与镜头划分照 `storyboard-spec.md` 镜头继承规则。

对白不必与参考视频逐句对位，按以下规则分配到各镜头：

- 镜头时长决定容量：按对白语言的口播语速估算朗读时长——英文每秒 2.5 个单词，中文每秒 4 个字。一个镜头装不下就把句子挪到相邻镜头，不改对白本身；挪无可挪才考虑调整镜头的时间码。
- 画面决定归属：讲某个卖点的句子落在展示该卖点的那个镜头，行动号召落在收尾镜头，提问落在还没给出答案的镜头。
- 复刻模式对原对白的出现位置与断句节奏另有继承要求，以 3a 的模式 reference 为准。

需求描述给出对白时严格按给出的原文安排：一字不改、不翻译、句子顺序不变，只决定每句落在哪个镜头。需求描述没有给对白时，才按 3a 模式 reference 的规则改写原片对白。

角色设定块与全表写完，用 `write_file` 写入 `storyboard.md`。

## 4. 镜头帧

为逐镜拉片表的每个镜头生成镜头帧：在参考视频的候选帧里挑出与 storyboard.md 中镜头描述构图相符的，逐帧撰写 visual_prompt，连同参考图提交生成。

**4a 取帧与补拍参考图**：两个工具调用在同一次回复中并行发起。

*取帧*：以参考视频的媒体 tag URL 调用 `plan_shot_frames`，返回的候选帧按 `storyboard.md` 逐镜拉片表的结构层级分板，一个结构层级一张候选帧预览板。板号即结构层级的顺序号，`shots` 是该结构层级各镜头的镜头号，板上每张候选帧标着 `S<镜头号>-<序号>`，即帧号。工具报某个时间码读不出时（报错会回显原文），修复流程：

1. 用 `read_file` 打开拆解文件，`edit_file` 把该时间码格式改成 `**[MM:SS.mmm-MM:SS.mmm]**`——只改格式不改数值，不动 Storyline 文字。
2. 改完重调 `plan_shot_frames`。同一份文件最多修 3 轮，仍失败则按缺口处理。本步不重新解析视频。

*补拍参考图*：给 3c 里没有参考图的人物与场景各补拍一张，调 `generate_anchor_sheet`，一个实体一格，有几个实体就传几条。同一批实体只补拍一次。

每格一条写成一行，照抄该实体锚点的原文；实体名不写——它是指代键，不是画面里的东西。

人物格是完整着装的全身像，部位逐项写全：上装、下装、足部各一处——足部在这里定，产品是鞋履时补一句「赤足」，把鞋位留给产品参考图。部位没写，模型按没有生成。

**【示例】**
*(4 个实体；条目以实际锚点为准。两条人物示例都写齐了上装、下装与足部。)*

```
全身正面平视，中性站姿。一位 30 岁上下的白人女性，中等身高，身材匀称，皮肤白皙，鹅蛋脸，鼻梁两侧有一些淡淡的雀斑。她留着深金色的头发，在脑后扎成一个低马尾。她穿着一件宽松的浅灰色细针织开衫，下身是米色的阔腿裤，赤着脚。她站在中性灰的无缝背景纸前，柔和的主光从正面打过来，人和背景之间有轻微的明暗分离。
全身正面平视，中性站姿。一个 5 岁上下的白人小女孩，身形瘦小，圆脸，脸色红润，一双蓝色的大眼睛。她留着浅金色的短发，长度到耳朵，发梢微微向外翘起，左边别着一个黄色的发夹。她穿着一条鹅黄色的纯棉连衣裙，短袖，裙子长到膝盖，赤着脚。她站在中性灰的无缝背景纸前，柔和的主光从正面打过来，人和背景之间有轻微的明暗分离。
空景全景平视，画面里没有人。一间入户门厅，地面铺着浅色的橡木地板，墙面下半截是白色的护墙板，上半截刷成米白色。门边装着一排挂衣钩，下面放着一张矮凳。
空景全景平视，画面里没有人。一条混凝土铺的社区步道，两侧是修剪过的草坪和低矮的灌木丛，再往外是白色的木栅栏。
```

**4b 看板、挑帧、写 visual_prompt**：板上的镜头号沿用拆解文件第 4 节的顺序，storyboard.md 继承同一份结构，两边的镜头才能逐个对上。动手前核对一次：`plan_shot_frames` 消息里报的镜头数、结构层级数（减去去掉的落版），与 storyboard.md 数出来的一致才继续；对不上就先回 3d 把结构修一致。然后用 `ReadMediaFile` 并行读取各板，逐板处理——根据板中帧的 `shots` 编号，将各镜头描述与候选帧按顺序建立关联。

1. **挑帧**：逐个镜头读该结构层级的 Storyline，在该镜头的候选帧里挑构图最相符的一张；相符只看景别、机位视角和主体的位置姿态，人物产品长什么样不看——候选帧来自参考视频，外观本来就是旧的，由参考图承载。镜头内构图有明显变化（动作前后两个状态、运镜起止两端）时才补第二张，两张分别对应变化前后。同一候选帧不重复挑；没有构图相符的候选帧时跳过该镜头，在输出里点名。
2. **写 visual_prompt**：按 `frame-prompt-spec.md` 为选中的每一张候选帧撰写一条。
3. **复核**：按顺序核对本结构层级选中的帧能够一一对应到它所属镜头的构图描述。

逐板处理完毕后组批：

1. **分批**：把挑选出的帧按顺序和场景分配，最多 4 张一组，相邻的帧不属于同一场景就顺延到下一组。每组整理成 `frames`：`[{no: 帧号1, prompt: 该帧的 visual_prompt}, {no: 帧号2, prompt: 该帧的 visual_prompt}, ...]`。
2. **写「全局参考设定」（global_reference）**：根据上面的分组，从 `storyboard.md` 的角色设定块取出本组出场的实体，每个实体一行。每行指向属于它的那张图：素材里有图的指素材图，补拍的指补拍参考图里它那一格。`reference_images` 第 N 张就是 `@ImageN`，两边编号必须对上。

   - 人物：`人物「人物名」外貌特征、穿搭设定严格遵循 @ImageN。`——单人也冠名；多人物时每人一行。外观由参考图承载，不附锚点原文。
   - 产品：`产品外观、结构、材质、颜色、品牌标识设定严格遵循 @ImageN、@ImageM。`；同一产品的全部视角图都列进这一行；多产品时每产品一行并冠以产品名，如 `产品A「儿童凉鞋」外观、结构、材质、颜色、品牌标识设定严格遵循 @ImageN`。
   - 场景：`场景环境、空间结构严格遵循 @ImageN。`
   - 补拍失败、实体没有任何参考图时，该实体回退成纯文本行，例如 `人物设定：该人物的锚点原文。`，不占 `@ImageN` 编号。
   - 不存在的类型不写。

**4c 生成**：对全部批次并行发起 `generate_shot_frames`，同步等待，生成需要数分钟。一批最多 4 帧，来自同一组 `frames`。
提交格式：
- `frames`：`[{"no": "S1-1", "prompt": "第 1 帧的 visual_prompt"}, {"no": "S2-1", "prompt": "第 2 帧的 visual_prompt"}, ...]`。
- `reference_images`：顺序即 global_reference 中 `@Image1..N` 的编号。
- `global_reference`：4b 撰写的整段文本。
- `target_aspect`：消息给定的目标画幅。

返回每帧 `{no, shot, url}`：`no` 是帧号，`shot` 是它所属的镜头号，`url` 即返回的视频帧。

每次调用都是一次真实生成，没有复用：已经拿到 url 的批次不再重发。每批成功后工具会把这批帧写进版记录 `frames/grids/<jobId>.json`，之后引用已生成的帧，以版记录里的 url 为准。某批失败时按局部缺口继续，其余批次照常往下走。

**4d 图片质量检查**：每批抽查 1 帧，用 `ReadMediaFile` 并行读取抽查帧的 url 和该批 `reference_images` 的全部参考图——比对凭像素，不凭锚点文字、不凭对图片的记忆。逐帧分两步看。

先看这一帧是不是一张完整的单幅画面。整批帧是从一张 2×2 网格图上机械切下来的，生成模型没按四等分排版时，切出来的每一帧都是坏的——帧内出现白色或黑色的分隔条、拼进半张别的画面、或有明显的跨画面切割痕。看到任何一种，说明这一批的网格排版不合规，整批 `frames` 重新发起，不用再看第二步。

画面完整的，再把抽查帧与该批参考图逐项比对，只看三项是否被遵循：

- **人物**：面容、发型、体型与着装是否与人物参照图同一人、同一套；产品是鞋履时足部对产品参照图，人物参照图的赤足不算不一致。多人物时逐人对。
- **产品**：外观、结构、材质、颜色、品牌标识是否与产品参照图逐项对上；多产品时逐个对。
- **场景**：空间结构与核心陈设是否落在场景参照图给定的环境里。

三项都对上就继续下一步。任一项对不上时把那一组 `frames` 重新发起一次，拿到重新生成结果后按同样要求检查。本步的重发一律按原入参原样再调——frames、参考图、global_reference 一个字段都不改，重发只是再掷一次骰子。同一批最多重发两次：一致性仍对不上的直接使用错图；画面仍不完整的按局部缺口处理，切坏的帧不交付。

global_reference 里回退成纯文本行的实体（素材没图、补拍又失败的）没有参考图可对照，不在本步核对范围。

## 5. 镜头组 prompt 生成

先按 `shot-spec.md`「镜头组切分」把结构层级自上而下累加合并成镜头组序列，输出合并结果（每个镜头组含哪几个结构层级、合计时长）；然后写各镜头组的 prompt，每张镜头帧紧跟在描绘它的那段文字之后（写法见 `shot-spec.md`），调用 `write_video_shots` 交付 `video_shot.json`。

## 输出要求

每完成一步，在发起下一批工具调用前先输出这一步的产物：

- 文本产物完整复述正文，不用"已写入文件"代替——改编模式与判定依据、素材事实清单、基础信息表（逐项标注来源）、角色设定块与逐镜拉片表、全局参考设定与逐帧 visual_prompt（每帧标明它对应哪个镜头）、视频尺寸与每个镜头组的时长和完整 prompt。
- 图像类产物报数量与归属：4a 报板数与每板对应哪几个镜头、补拍参考图逐格对应哪个实体，4c 报成功与失败的帧号，4d 报抽查了哪些帧号与逐项结论。
- 输出是简短陈述，不加寒暄。

最终回复只做收尾：交付需要人工复核的项（品类冲突、语速偏紧、推断置信度低的字段）；都没有时一句话确认交付完成。

## 缺口处理

工具报错时先从错误信息判断重试是否可能改变结果，可能时重试一次；个别步骤另有专门的处置动作，见该步。处置后仍不行的一律按两级归类：

- **全局缺口**——某一步的前置输入不可用（没有参考视频、拆解文件重新解析后仍异常）：停在已完成的产物，下游不做。
- **局部缺口**——产物部分残缺（个别批次生成失败、个别镜头组缺帧）：能交付的照常交付，跳过受影响的部分。

两级都在最终回复里如实列出缺什么、影响哪个产物。信息有缺口时能推断的推断并标注来源；不为填缺口编造素材事实，不把推测写成可见事实。

## 重做范围

按影响范围定位重做起点，只重做受影响产物及其下游，上游产物不动。镜头帧按结构层级增量重做：取帧只依赖参考视频与其拆解文件，选中的候选帧与 visual_prompt 只承载构图与动作（不含外观），能复用就复用——已生成的帧查 `frames/grids/` 版记录，只重新处理受影响的结构层级：

| 修改内容 | 处理动作 |
|---|---|
| 改编模式、品类、卖点、受众等基础信息 | 重新推导，重做 `storyboard.md` 及下游：参考视频与拆解文件未变则取帧复用；受影响的结构层级重新挑帧、重写 visual_prompt 并重新生成，再重做镜头组 prompt 表 |
| 创意方向、镜头结构、动作、Storyline | 修改 `storyboard.md`：内容改动影响哪些结构层级，就重新挑那些结构层级的帧、重写 visual_prompt 并重新生成（其余复用）；改动触及 global_reference 的内容（实体名、出场实体增减、参考图分配）时选中的候选帧与 visual_prompt 可复用、以新 global_reference 重新发起全部批次；之后重做镜头组 prompt 表 |
| 人物设定（外貌、服装、发型）或产品替换 | 更新 `storyboard.md` 角色设定块与受影响 Storyline；取帧、选中的候选帧与 visual_prompt 复用，锚点变了的实体重新补拍参考图，以新参考图与新 global_reference 重新发起全部批次，重做镜头组 prompt 表 |
| 镜头组 prompt、参考图分配 | 只重做镜头组 prompt 表（镜头帧复用） |

只改被点名或受影响的局部，不主动推翻整体结构。

## 硬约束

- 全程不提问、不等待确认，从起点一直做到可交付为止：逐镜拉片表 → 镜头帧 → 镜头组 prompt 表三级产物在同一次回复链里连续产出，每个产物完成即继续下一步。
- `storyboard.md` 只经 `write_file` / `edit_file` 写入；镜头组 prompt 表只经 `write_video_shots` 交付，不用 `write_file` / `edit_file` 写它或它的副本。
- 不编造素材观察、视频解析结果或产物状态；引用素材时使用消息里媒体 tag 的 URL，不凭记忆跳过素材核对。
- 镜头帧只经 `plan_shot_frames` 取帧、`generate_shot_frames` 生成，补拍参考图只经 `generate_anchor_sheet` 生成，以工具返回值为准复述结果，不声称做过工具返回之外的生成。
